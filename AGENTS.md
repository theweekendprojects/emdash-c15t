# AGENTS.md — emdash-c15t

Context for an AI agent (or a human) opening this repo cold. The README is for users. This file is the *why*, the
architecture, and the facts about EmDash and c15t that were checked the hard way.

## What this is

A per-site cookie-consent plugin for EmDash CMS (GDPR/TDDDG). c15t runs the banner in the browser. This plugin injects it,
gates vendor scripts and embeds, and stores a PII-free consent proof in the site's own storage. Published to npm as
`emdash-c15t` (MIT). The plugin id stays `emdash-privacy`, because the routes, stored data and settings keys use it.
Renaming the id would orphan existing data.

## Verified EmDash facts (checked against the installed EmDash, not docs alone)

- **Settings**: `ctx.settings.list()` returns `{key, value}` with keys relative to `plugin:<id>:settings:`. One query.
  The `settingsSchema` auto form is NOT declared on purpose: it would write values past our validation.
- **Storage**: `storage.consents.query()` caps `limit` at **100**. Asking for more silently returns 100.
  `orderBy` on a JSON field defeats the table's index and re-sorts every match on each page: 7 000 rows took 13 s.
  Do not pass `orderBy`. With none, EmDash pages in `(created_at, id)` order on the table's own index (0.7 s for the same rows).
- **Raw responses are limited to 8 MiB.** EmDash throws past it and the client gets a 500. The export stops at 7 MiB and
  returns 413 with a `from`/`to` hint instead.
- **`ctx.site.url` can be an empty string** (it is on the staging Worker). Use `||`, not `??`, wherever it falls back.
  `siteIdFrom()` is the one place that does.
- **Plugin storage is per site on emdash-multisite** (`_plugin_*` tables get a `$slug` suffix, `isSiteTable` in rewrite.ts).
  So the export and the record count do not filter by `siteId`; it is only a label in the file.
- **Private routes** (`public` not set) need a session or an API token. A session also needs `X-EmDash-Request: 1`, or
  EmDash returns `403 CSRF_REJECTED`. A token (`Authorization: Bearer ec_pat_...`) needs the `admin` scope for the export.
- **Raw responses** (`response: "raw"`): EmDash keeps only an allowlist of headers and sets `nosniff` and
  `private, no-store` itself. Do not set them in the route.
- **Errors with status**: `throw PluginRouteError.forbidden(...)` becomes the HTTP status. `pluginResponse()` is the raw
  response builder.
- **Request object**: `ctx.request.headers` is a real `Headers` on trusted routes, not a plain record. `Object.entries`
  on it is empty. This bug shipped once and was caught by a test.
- **Page fragments**: `event.page` is `PublicPageContext`: `path` and `locale` exist, there is no `cspNonce`.

## Facts about c15t (3.0.0, pinned)

- The offline transport needs `match: { isDefault: true }` for every visitor, and `scopeMode: "permissive"` when
  `categories` is a subset.
- `clearOnRevocation` takes exact names or a trailing-`*` prefix only.
- `ui.banner: false` hides the banner and keeps the rest. `ui.trigger: false` hides the reopen button.
- Google's helper (`gtag`) defaults to `loadMode: 'always'`. We pass `'after-consent'`, so nothing reaches Google before
  consent. Microsoft UET sets `alwaysLoad`, so it is not offered as a preset.

## Non-obvious decisions

- **Stored time is the server's clock.** `givenAt` from the browser is accepted and ignored.
- **Export is never truncated.** Over the size limit it answers 413 with the `from`/`to` hint. `from` is included, `to` is not.
- **Owner download links are public and signed.** A browser link can't send `X-EmDash-Request`, so `consent-download` is a
  public raw route. Its only check is the HMAC over `from`, `to` and `exp`, with a secret created once in plugin KV. Changing
  any of them, or going past `exp`, fails. A link is made fresh on every admin page load. Don't loosen this route without a
  replacement check: it returns every consent record for the range.
- **Strict CSP is a documented limit.** The loader is an inline script and imports from `blob:`. EmDash refuses JS from
  plugin routes and gives fragments no nonce, so a site with `script-src 'self'` gets no banner. README says what to allow.
- **Save while disabled** returns `{ok: true, stored: false}`. An error would make c15t retry the save forever.
- **Embed-only sites** (no services) still start c15t with the banner hidden and no reopen button. Otherwise a
  `ConsentEmbed` placeholder could not open the dialog.
- **Bundle cache**: a cached copy runs only if its SHA-256 (first 12 hex) equals the build hash. Anything else is removed
  and refetched. Without SubtleCrypto nothing is cached. Other versions' keys are removed.
- **Lazy purge** runs in `/save`, once a day, up to 20 pages (2 000 rows). Cron does up to 50 pages. Pages are re-read
  from the start after each delete, so no cursor is needed.
- **Dependencies**: `zod` is a runtime dependency (pinned). The `@c15t/*` packages are build-time only (devDependencies).
  The published package does not import them at runtime.
- **Services format** is strict: unknown fields, bad IDs, non-https URLs, and mismatched preset categories are errors.
  Stored invalid config shows an admin warning and the valid entries still load.

## Verification

```bash
npm install --legacy-peer-deps   # --legacy-peer-deps: npm's peer resolver fails on vitest's optional browser peers
npx playwright-core install chromium   # once, for tests/browser.test.ts (or set CHROMIUM_PATH)
npm run build:client             # REQUIRED before tests: writes src/assets.generated.ts and dist/banner.js
npm run typecheck
npm run selfcheck
npm test                         # tests/: EmDash runtime + SQLite, real browser, Astro build of ConsentEmbed
```

Node 22.23.4 or newer (Astro 7.4 refuses older). CI pins 22.23.5 and runs EmDash 1.2.0 (the peer floor) and 1.6.0 (the
dev version).

The test harness stubs EmDash's `virtual:emdash/*` modules, as EmDash's own tests do (`vitest.config.ts`). The browser
test serves the real runtime output and the real bundle, and intercepts vendor requests.

## Release checklist

1. `npm run build:client`, `npm run typecheck`, `npm run selfcheck`, `npm test`. All green on Node 22.23.5.
2. `npm pack --dry-run`: 28 files, including `THIRD_PARTY_LICENSES.md`, no `*.selfcheck.ts`, no `tests/`.
3. `npm audit --omit=dev` is clean. Dev findings are acceptable only when they are dev tooling and fixed upstream.
4. Bump `version` in `package.json` and the changelog heading together.
5. `npm publish` (needs the maintainer's npm login). Then deprecate old `emdash-privacy` versions.
